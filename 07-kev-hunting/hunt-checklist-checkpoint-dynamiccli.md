# Hunt checklist — Check Point DynamicCLI local privilege escalation (CVE-2026-123039)

Work top to bottom. Check the box when done, note what you found.
Detection and forensic triage only — do not attempt to reproduce the flaw or run exploit code.

This pack is the second layer of the PHP2Shell incident. It does **not**
duplicate `hunt-checklist-php2shell.md` — read that pack first for the
initial-access layer (CVE-2026-109618 / CVE-2026-109619, added 2026-10-26,
federal due 2026-10-29). This pack starts where that one ends: a local user
on the gateway turning PHP2Shell's portal-account shell into root, and what
came after.

## 1. Am I even in scope?
- [ ] Product is a Check Point gateway / firewall running Gaia OS. The flaw
      is in the DynamicCLI daemon (`dynamic_server`), which runs as root and
      listens on the world-writable local socket `/tmp/dynamic_socket`
      (mode 0777) without authenticating connecting processes.
- [ ] Severity: CVSS **7.8** (CWE-732 / CWE-862, per the CISA KEV feed).
      An authenticated local user can send a command to the socket and have
      it executed as root.
- [ ] In CISA KEV: added 2026-11-13, federal due 2026-11-16, forensic
      triage Yes, ransomware use Unknown.
- [ ] Fixed in the November Jumbo Hotfix: **R82.20 Take 14+ / R82.10 Take
      52+ / R82 Take 132+ / R81.20 Take 174+** (vendor advisory sk1000362).
- [ ] Stopgap, per the vendor: `dbset process:dynamic_server off` — then
      verify the daemon is actually stopped; a stopgap is not a patch.
- [ ] Already patched → still do §5 if the gateway ran the PHP2Shell window
      unpatched. Patching does not remove a planted webshell or backdoor.

## 2. The chain (initial access → root → ESXi)
- [ ] Initial access: PHP2Shell (CVE-2026-109618 / CVE-2026-109619)
      unauthenticated RCE as the portal account, in the window 30 Oct to
      4 Nov. See the php2shell pack for that layer.
- [ ] Local privilege escalation: write a command to the world-writable
      `/tmp/dynamic_socket`; the root daemon `/usr/bin/dynamic_server`
      executes it as root. That is CVE-2026-123039.
- [ ] Webshells: `zz*.tpl` webshells (key `zz2026`, `/tmp/.up.tpl`,
      `challenge_render.tpl`).
- [ ] Backdoor (TSGA): `/tmp/CPconfigdaemon`, `slot_CPconfigdaemon`,
      `/tmp/.bd.log`, `/lib/libcpfwcommon.so`, TCP **11072**,
      `/tmp/.p_sock`.
- [ ] Lateral movement and destruction: the `gogo` scanner, then SSH to
      ESXi as `vpxuser`, then the `destroy_v6` wiper and
      `DREAM_ANNEXATION.txt`.
- [ ] Scale, per Check Point Research: "a couple of dozen" systems. Wave 1
      (30 Oct) hit Israeli organisations and was destructive; wave 2
      (2 Nov) hit multiple countries with no destruction observed.
- [ ] Attribution is **explicitly unresolved**. Do not attribute this
      activity to UNC5221, to China, or to any other named actor — no
      primary source used here does.
- [ ] Attacker IPs published by Check Point Research: 130.94.19[.]204 and
      130.94.19[.]168 (defanged here; in sample logs only documentation
      ranges are used).

## 3. The signals (detection) — vendor checks from sk1000362
Log source: `/var/log/dynamicCli.log`. The vendor checks are verbatim greps
on that log; the detector implements them.

- [ ] Non-wrapper `Received` lines — `Received` lines that did not come
      through the legitimate Clish wrapper (NON_WRAPPER_RECEIVED).
- [ ] `Received = #return_value#` — the daemon returning a command's
      output, i.e. a command was executed through the socket (SYSTEM_SINK).
- [ ] Exploit keywords: `id;` / `whoami` / `/etc/shadow` / `ncat` /
      `nc -` / `/dev/tcp` / `curl` / `wget` / `base64` / `useradd` /
      `authorized_keys` (EXPLOIT_KEYWORD).
- [ ] Post-fix: `Rejected connection from unauthorized uid` — a blocked
      attempt. That is evidence the fix is working, not an incident by
      itself (§4).
- [ ] PHP session marker: `/opt/CPcvpn-*/tmp/` containing
      `upload_progress_pwn`; hundreds of segfaults in the same window
      (per the vendor research).

## 4. Correlate
- [ ] Same gateway: SYSTEM_SINK or EXPLOIT_KEYWORD → incident
- [ ] NON_WRAPPER_RECEIVED alone → suspicious; triage the command. A
      non-wrapper `Received` line is a vendor grep target, not proof of
      execution by itself.
- [ ] REJECTED_UID alone → blocked attempt (the patched daemon refused the
      connection). Confirm the rejection happened and check whether the
      same source tried other paths; do not open an incident on it alone.
- [ ] Any §3 signal on a gateway that also ran PHP2Shell unpatched → treat
      as the same incident, not a separate one; go to §5.

## 5. Forensic triage (CISA KEV `forensicTriage: Yes`)
A gateway that ran unpatched while internet-exposed must be checked for
compromise, not merely patched. Patching does not remove a planted webshell
or backdoor.

- [ ] `/tmp/dynamic_socket` permissions and every process that connected to
      it in the window; `/var/log/dynamicCli.log` for §3 signals.
- [ ] Webshells and backdoor files: `zz*.tpl` (key `zz2026`),
      `/tmp/.up.tpl`, `challenge_render.tpl`, `/tmp/CPconfigdaemon`,
      `slot_CPconfigdaemon`, `/tmp/.bd.log`, `/lib/libcpfwcommon.so`,
      TCP 11072, `/tmp/.p_sock`.
- [ ] Hashes (SHA-256, verbatim from Check Point Research):

      wiper, `DREAM_ANNEXATION.txt`.
- [ ] If anything above is unclean: isolate, rebuild the gateway from a
      known-good image, rotate credentials (gateway, VPN, ESXi, and anything
      the gateway could reach), then bring the fixed build online. Patching
      alone does not remove a planted shell.

## 6. Hardening while you patch
- [ ] Apply the November Jumbo Hotfix takes from §1 for your version, and
      confirm the daemon no longer listens on a world-writable socket.
- [ ] Until patched, the vendor stopgap is `dbset process:dynamic_server
      off` — verify it took effect; do not assume.
- [ ] Tighten `/tmp` permissions where the platform allows it, and alert on
      new listeners on local sockets.

## Correlation
- [ ] SYSTEM_SINK or EXPLOIT_KEYWORD on one gateway → incident
- [ ] NON_WRAPPER_RECEIVED alone → suspicious; triage the command
- [ ] REJECTED_UID alone → blocked attempt; confirm, then close with the
      rejection evidence
- [ ] No §3 signals, gateway patched before exposure → close with the
      version evidence from §1


keywords + `#return_value#` echo + download-tool keyword), one
`[SUSPICIOUS]` (gw-04: lone non-wrapper `Received` line), and one

legitimate Clish wrapper lines never fire. All lines are synthetic
